# 二、学生对课题的综合理解

## （一）课题目的及意义

小说持续创作不仅涉及当前段落的表达，还需要维护人物经历与关系、世界观规则、大纲和前文章节。随着内容积累，作者需要反复查阅资料、调整情节，并判断新内容是否符合已有设定。大语言模型在语言理解与生成方面的发展，为构思、续写和修改提供了技术条件[1-2]。本课题关注如何把这些能力放入作者日常使用的创作系统，使资料管理、正文编辑和智能辅助相互衔接。

国内相关研究已涉及生成控制、叙事生成和长文本处理。提示学习与受控文本生成综述分别从任务表达、生成条件等方面整理方法，为组织作者要求提供参考[5-6]。中文故事结尾生成研究采用双向对比训练，并结合自动指标和人工评价考察结果，其实验对象是结尾句，不能直接推广到长篇章节续写[7]。长文本推断综述讨论计算、存储与时延问题；幻觉及安全隐私综述则说明生成可靠性和数据保护需要单独考虑[3-4,8]。这些研究支持问题识别，不直接证明本系统的上下文方案有效。

创作者使用AI的方式也是相关研究的重要内容。相关访谈研究显示，部分受访作者会限制AI用途，并保留自身构思和选择[9]。引用网络文学创作者相关研究时，应严格按照原文研究范围表述，不将有限样本的研究结论扩大为整个行业的普遍结论。理论与案例研究也讨论作者主体性和数据依赖，强调作者对工具反馈的判断[10]。另外，两篇Web系统案例展示了角色、模块、数据库和服务实现的组织方式，可供本课题工程设计参考，但不构成框架性能或安全优势的证明[11-12]。

国外研究从协同操作、长故事生成及一致性评价等方面展开。Wordcraft在故事编辑器中提供预设和自定义生成、修改操作，研究作者如何使用模型建议，其短故事实验不能代表长期小说创作效果[13]。Re³以规划、起草、重写和编辑组织长故事生成，在生成过程中更新计划与前文信息[14]。Lost in Stories研究人物、时间和世界规则等一致性错误，并通过基准与检查方法进行专门评价[15]。这些工作为作者控制、上下文选取和冲突提示提供了参考；本项目的Writing Skill、Context Management及具体调用流程仍需自行设计与验证。

本课题拟设计并实现基于Spring Boot、Vue与大语言模型的Web小说智能辅助创作系统，将作品、卷章节、创作资料、正文编辑和过程管理与智能辅助结合。AI生成内容作为候选，由作者决定采用、修改、重新生成或放弃，未经确认不覆盖正式稿件。其实际应用意义是为持续小说创作提供统一的资料与写作环境；软件工程实践意义则是综合运用需求分析、架构与数据库设计、前后端开发、认证、AI接入和测试方法，考察模型能力如何与真实业务流程结合，不预先承诺创作质量或效率提升。

## （二）课题研究的主要内容

课题拟围绕创作者和轻量管理员分析需求，设计前后端分离架构及业务数据关系。常规创作部分以邮箱认证与权限、作品与卷章节管理、富文本正文编辑为基础，组织人物及关系、世界观、大纲、素材和灵感等创作资料，并设计写作计划、创作统计、创作激励与沉浸体验等辅助功能。稿件管理包括TXT导入、导出和版本历史。

智能创作部分拟通过Writing Skill组织大纲规划、人物塑造、情节构思、上下文续写、文本润色和一致性检查六类任务，明确输入、资料需求、提示词与输出处理。Context Management将按任务组织上下文；MCP Resource和Tool负责访问已保存资料及必要查询能力；外部LLM生成候选或检查结果。设计将重点说明这些部分如何与正文编辑及作者确认衔接。

系统完成后拟开展功能、性能、安全性和可靠性测试，针对续写、一致性检查及作者确认设置专项验证，并单独检查真实MCP调用链路。

## （三）拟解决的主要问题和最终目标

**A. 拟解决的主要问题**

一是持续积累的作品设定、人物、大纲与章节需要统一组织，避免创作取材与正文脱节；二是不同智能任务所需信息不同，续写需要结合前文和设定，不能把全部资料无差别提交模型；三是人物、时间、情节和世界规则可能发生冲突，需要给出可复核的依据，而非将所有变化判为错误；四是候选与正式稿件需要明确分离，使作者掌握保存决定权；五是智能任务访问资料需要统一协议入口，同时保持作品归属和访问权限。课题拟处理上述软件应用问题，不以彻底消除长篇一致性错误为目标。

**B. 最终目标**

完成可运行的Web小说智能辅助创作系统，覆盖已确认的认证、创作业务和轻量管理员功能，落实六类Writing Skill、上下文管理、外部LLM调用及作者确认。上下文续写和一致性检查将通过真实MCP Resource与Tool取得所需资料。完成普通功能、非功能、智能辅助专项及MCP链路测试，按记录判断功能和流程是否符合设计要求。

任务书提出的页面响应和多用户并发要求将作为后续非功能测试目标，具体测试条件和统计口径将在系统测试阶段确定。最终提交完整前后端源码、Skill清单与提示词说明、MCP设计及工具接口、数据库文档和建表脚本、部署说明、测试记录、操作演示及毕业论文。

## （四）拟采用的研究方法或技术方案

研究将采用文献分析、需求分析、系统建模、分模块开发和软件测试相结合的方式。先将任务书要求落实为角色职责、业务流程及数据关系，再按模块开发和联调，并建立需求与测试记录的对应关系。智能辅助部分拟在具有明确人物、情节和世界观设定的测试材料上，对续写承接、约束遵循和一致性检查进行专项验证。

Web部分计划采用Vue 3、Element Plus组织界面，Vue Router管理路由，Pinia管理状态，Axios访问REST接口，ECharts展示创作数据。后端采用Java 17、Spring Boot 3.5.16、Spring MVC和MyBatis-Plus 3.5.17，以MySQL持久化业务数据，使用邮箱注册登录、验证码及JWT落实既定认证流程。Git/GitHub用于版本管理。普通业务按照“Vue—REST接口—Controller—Service—MyBatis-Plus—MySQL”处理。

AI部分由Writing Skill组织智能创作任务，Context Management结合作者要求、当前编辑内容及已有资料选择、裁剪和组合上下文。MCP为访问系统内已保存的创作资料和必要查询能力提供协议接口，外部LLM根据上下文与任务要求生成候选内容或检查结果。

MCP Client位于后端AI模块，MCP Server位于同一Spring Boot应用，通过真实MCP协议链路通信。Resource用于访问作品资料，Tool用于参数化查询。MCP Server复用业务Service，不替代其职责，Vue不直接访问MCP Server。

智能辅助流程概括为：Vue前端→Spring Boot后端→Writing Skill→Context Management→按需通过MCP访问创作资料→构建模型上下文→外部LLM→返回候选结果→作者确认→通过普通业务接口保存。作者可采用、修改、重新生成或放弃候选，未经确认不能覆盖正式正文。当前输入可直接进入上下文管理。具体模型、SDK及编辑器组件将在兼容性与实际条件核验后确定。

## （五）课题预期结论或过程中的特色、创新点

本课题的主要特色拟凝练为以下两项，定位于小说创作场景的应用设计，不将通用框架或普通管理功能作为创新。

1. **面向持续创作的任务化智能辅助。**通过Writing Skill将六类任务的目标、输入、资料需求、模型调用及结果处理组织起来，使辅助操作与当前作品和编辑内容关联。候选内容由作者选择、修改、重新生成或放弃，正式保存以作者确认为前提。作者对生成内容的决定权将贯穿智能辅助流程。

2. **上下文组织与标准化资料访问相结合。**由Context Management确定任务所需信息，利用真实MCP Resource/Tool访问系统已保存的创作资料，再结合当前输入进行裁剪和组合。重点是区分资料访问、上下文组织和模型生成的职责，使同一作品资料能够服务不同辅助任务，而非发明新协议或宣称协议带来质量增益。

预期形成可运行系统及配套设计、实现与测试材料。系统完成后计划通过功能、非功能、智能辅助专项和MCP链路测试，分析主要业务是否符合要求、辅助流程有哪些适用条件及限制。生成质量与一致性检查表现以实际结果为准，不预设提升，也不将尚未验证的方案表述为已取得的创新成果。
