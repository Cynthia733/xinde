# 一、学生在开题前的准备工作

（一）课题方向与任务要求的梳理

围绕《基于 Spring Boot+Vue 与大语言模型的小说智能辅助创作系统设计与实现》，已结合正式任务书，对研究对象、用户角色、主要业务和成果要求进行了梳理。课题面向小说创作者，以网页端为主要使用形式，将日常写作管理与大语言模型辅助结合。用户分为创作者和轻量管理员，重点围绕作品管理、创作资料管理、正文编辑及智能辅助展开。在前期需求梳理中，已将任务书要求与详细功能进行对应整理，明确系统角色、实施范围和后续工作内容。

（二）软件开发知识与工程准备

结合软件工程专业学习内容，已整理本课题所需的后端、前端、数据管理和接口协作知识，确定前后端分离的技术路线。后端围绕Java、Spring Boot、Spring MVC、MyBatis-Plus和MySQL梳理请求处理、业务逻辑与数据持久化的分工，明确JWT认证与接口权限要求。前端围绕Vue 3、Element Plus、Vue Router、Pinia和Axios，整理页面组件、路由、状态及网络请求之间的关系，并梳理RESTful API与JSON交互。Git和GitHub已纳入版本管理方案。项目基础版本已统一为Java 17、Spring Boot 3.5.16和MyBatis-Plus 3.5.17，已有Maven构建成功记录；业务模块与AI调用尚未完成。

（三）中外文献查询与阅读资料准备

前期已围绕大语言模型与文本生成、小说辅助创作和Web系统工程实践查询资料，整理出固定的15篇正式参考文献，其中中文12篇、英文3篇，发表年份为2022—2026年。相关论文已取得全文并完成AI辅助全文核读，形成逐篇阅读卡与证据矩阵，记录研究对象、方法、结论、页码及使用限制。记录用于辅助回查，拟引用内容仍需本人核实。

文献材料分为几个相互关联的方向：大语言模型综述帮助梳理技术背景，幻觉、安全和隐私研究用于识别模型应用的限制[1-4]；提示学习、受控文本生成、中文故事结尾生成及长文本推断研究，为理解任务要求、生成约束和上下文处理提供资料[5-8]；网络文学研究用于了解创作者使用AI时的选择和工具关系[9-10]；两篇Web工程案例用于比较角色、模块、数据表和实现的组织方式[11-12]；英文文献分别涉及协同故事写作、长故事规划生成和一致性评价[13-15]。短故事结尾实验不能直接推广到长篇续写，工程案例也不能证明框架的性能或安全优势。

（四）智能创作任务与上下文方案准备

结合文献和任务书，已将大语言模型定位为提供建议、候选文本和检查提示的辅助工具。现阶段形成了LLM、Writing Skill、Context Management与MCP相配合的项目设计思路。Writing Skill用于组织大纲规划、人物塑造、情节构思、上下文续写、文本润色和一致性检查六类任务，梳理各任务的目标、输入、资料需求及结果处理。Context Management负责结合作者要求、当前编辑内容和已有创作资料，选择、裁剪并组合上下文。二者属于项目设计，不等同于提示学习或模型训练。

通过相关研究的比较，已明确需要分别关注前文承接、设定遵循和内容一致性，不能仅凭文字流畅判断结果合适，也不能把合理新增情节直接视为幻觉。已明确候选内容由作者采用、修改、重新生成或放弃，未经确认不覆盖正式稿件。文献在这些方面提供了参考，但本项目具体方案是否适用，仍需后续实现和测试。

（五）MCP机制与接入边界准备

已围绕MCP基本机制整理资料，并确定后端作为Host，在后端配置MCP Client，由同一后端应用内嵌MCP Server。Vue通过普通业务接口发起请求，不直接访问MCP Server。已明确以Resource表达可读取的作品设定、人物、大纲和章节等资料，以Tool提供带参数的章节窗口查询，采用真实协议通信，而非用普通Java方法调用代替MCP。上下文续写与一致性检查是后续验证真实资源读取和工具调用的重点。

目前还区分了MCP与上下文管理的职责：作者当前要求、选中文本等可直接进入上下文管理，系统中已保存的资料按需通过MCP取得，查询仍复用业务Service。模型输出经作者确认后由普通业务接口保存，不通过模型自动写入工具覆盖正文。这些属于接入方案准备，尚未验证MCP调用成功；SDK兼容、权限隔离、调用追踪和故障处理仍需实施核验。智能辅助以调用外部模型和组织创作资料为主要实现方向。

（六）业务功能与数据组织准备

已围绕邮箱认证、作品及卷章节管理、富文本正文编辑，梳理创作者的基本操作过程；对人物及关系、世界观、大纲、素材和灵感，明确归属与取材用途。写作计划、创作统计、激励与沉浸体验、稿件工具及轻量管理员管理也已纳入需求范围。数据准备目前集中在业务对象、关联和访问边界的分析，尚未完成数据库表及正式业务数据建设。

TXT稿件导入已确认为正式需求，包含整本作为单章节导入和按标题规则自动分章两种方式。已明确上传解析后先展示预览，由作者检查、调整并确认，再进入统一作品和卷章节数据模型，供后续编辑和智能辅助使用。导出与版本历史继续保留。上述流程尚未完成实现与验证。

（七）论文组织与验证准备

已形成研究规划、文献证据分配和经确认的论文目录V1.0，并整理了摘要、前言及第一章阶段性稿件。已将需求、设计、实现和测试的对应关系作为后续工作要求，初步区分普通功能、非功能、智能辅助专项及MCP链路的验证对象。任务书中的页面响应和并发要求已记录为待验证目标，尚无系统实测结果。代码、数据库文档、Skill及MCP说明、部署说明、测试记录与操作演示已列入交付清单。当前成果为前期准备材料，不包含完整系统及测试成果。
