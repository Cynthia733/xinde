# 开题报告正式要求核对与现有材料映射 V0.1

核对日期：2026-09-30。性质：要求核对与材料映射，不是完整开题报告。依据正式任务书、PROJECT_CONTEXT v1.6、已确认目录V1.0及当前12/15篇全文阅读记录；采用ARS-Codex规划与题录核查流程。

正式题目：**《基于 Spring Boot+Vue 与大语言模型的小说智能辅助创作系统设计与实现》**。

## 1. 学校、导师要求及依据

八个填写项、准备工作1500字以上、分条填写、15—20篇近年文献且含英文，依据本轮用户转述的学校系统和导师通知。本轮没有登录学校系统，输入框上限、参考文献是否计入字数、实际开题截止日尚未核实。除明确的1500字下限外，下列篇幅均为建议，不是学校硬性标准。

核对材料：任务书原件、v1.6、任务书对齐报告、研究规划及锁定目录、最终15篇计划、阅读笔记、证据矩阵；摘要V0.3、前言V0.2、1.1 V0.2、1.2国内/国外/综合V0.2、1.3 V0.2、1.4 V0.1、1.5 V0.1；本地12篇PDF题录及其已有核读记录。没有重新精读剩余3篇。

任务书是最低范围，不是功能上限。v1.5保留功能继续有效，但使用v1.6的最新解释。开题报告应描述拟开展工作，不能复制完成态论文预稿作为已经实现、测试的证明。

MCP Client/Server为后端协议角色，可同一Spring Boot应用部署，但必须真实transport通信。Resource表达创作资料，get_chapter_window为带参数章节查询Tool；续写和一致性检查须在关闭fallback条件下实际经过Resource+Tool。用户要求、选中文本和未保存编辑内容可以直接进入Context Management，不强制所有输入经MCP。降级、权限、调用追踪分别验证，不伪装协议成功。

TXT支持整本单章节及规则自动分章，解析预览、检查调整、确认后进入统一作品/卷章节模型；保留导出，不新增其他导入格式。富文本、素材管理、灵感速记、版本管理、重新生成、操作演示和部署说明均为任务书必做。v1.5既有激励、沉浸和趋势等功能不能因开题篇幅聚合而取消。
