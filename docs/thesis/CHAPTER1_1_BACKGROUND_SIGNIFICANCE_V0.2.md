# 1.1 研究背景与意义

大语言模型在语言理解和文本生成方面的研究进展，为数字文本创作提供了新的技术条件[P02]。对于小说创作，生成文字只是其中一个环节。作品通常需要围绕人物、世界观和故事大纲持续展开，章节之间也存在情节上的联系。与一次完成的短文本任务相比，本课题关注的创作过程需要保存并反复使用这些资料。篇幅增加后，作者不仅要考虑下一段如何表达，还要查阅前文、核对设定和调整构思。这使小说辅助创作成为同时涉及文本处理与资料管理的软件应用场景。

从创作工作过程看，若人物资料、大纲和正文分别保存在不同位置，修改设定时就需要检查相关内容是否一致。例如，调整人物经历后，已有章节中的叙述可能也需要复核；尚未写入正文的情节安排，则应与已经发生的故事内容区分。针对模型生成长故事的研究，将人物、时间和世界规则等冲突纳入一致性分析[P15]。对本课题而言，检查提示需要结合当前作品的具体设定，由作者判断是否构成矛盾。系统还需适应作者在构思、续接和修改之间切换的工作需要。

大语言模型负责生成文本，系统还需管理作品资料、准备所需上下文，并区分生成的候选内容与正式稿件。长故事生成研究在续写时重新组织计划与已生成内容，为按任务选取信息提供了参考[P14]。本系统需要保存和维护创作资料，并按当前任务整理相关内容，供模型生成时参考。人机协同写作研究还发现，未被原样采用的建议也可能启发作者[P13]。系统应保留作者审阅候选文本的环节，由作者比较、修改并决定是否写入正式稿件。

本课题的实际应用意义在于，将分散的创作信息与智能辅助操作纳入统一的Web工作环境。作者可围绕同一作品整理资料、编辑章节并查看写作进度，使资料维护与正文创作保持联系。相关访谈中，部分网络文学作者会主动限制AI的使用范围，并以自己的构思指导生成[P09]。本文据此关注作者的决定权，将智能辅助定位于提供构思参考、候选文本和检查提示。是否采纳建议仍由作者判断，系统的价值不以自动生成篇幅替代作者的创作选择。

本课题也为软件工程综合实践提供了具体的应用场景，将前后端分离、数据管理、身份认证和业务模块设计用于完整的Web创作系统。在此基础上，将大语言模型、Writing Skill、上下文管理和MCP接入日常创作操作，探索智能辅助功能与传统Web业务的结合。这项实践关注从资料准备、任务调用到作者确认的完整过程，系统是否满足创作辅助需求仍需通过实际实现与测试检验。
