## 分层与调用关系

1. 浏览器前端：Vue 3与Element Plus组织创作界面，Vue Router/Pinia组织导航与状态，Axios发送业务请求，ECharts展示个人创作统计。
2. Spring Boot后端：同一应用内分别组织业务接口与业务处理、AI任务编排、MCP协议访问。图中三个区域是职责分组，不是三个服务或进程。JWT认证和权限校验为拟实现功能。
3. 数据与外部模型：MySQL保存用户、作品、章节、创作资料及相关记录；外部LLM提供候选生成和辅助分析。模型供应商及版本未锁定。

普通业务路径：前端 → Spring MVC业务接口 → 业务Service → MyBatis-Plus → MySQL。

AI路径：前端 → Spring MVC业务接口 → Writing Skill → Context Management → MCP Client → 真实Streamable HTTP回环通信 → MCP Server的Resource/Tool → 业务Service查询授权资料 → MyBatis-Plus → MySQL。资料沿调用链返回Context Management，由其选择、裁剪、组合后交给LLM调用服务，再调用外部LLM。图中省略反向返回箭头以避免交叉；“取得资料并组织上下文”表示取材完成后的生成步骤，不表示绕过MCP。

Writing Skill包含六项既定任务：大纲规划、人物塑造、情节构思、上下文续写、文本润色、一致性检查。至少上下文续写与一致性检查须实际使用Resource及Tool链路；图不展开具体工具契约。

MCP Client与Server均在同一个Spring Boot应用中，仍须通过实际HTTP传输及MCP协议消息通信。Server复用业务Service，不绕过其权限和业务规则直接访问数据库。Vue只访问业务接口，不直连MCP、数据库或外部LLM。

## 当前输入与作者确认

当前编辑器未保存正文、选中文本和作者要求可由业务请求直接送入Context Management，不必先写入MySQL再通过MCP读取。图中的MCP支路表达已保存资料的访问，不表示所有输入均经过MCP。

模型结果经后端返回前端展示，作者决定采用、修改或放弃；确认后才通过普通业务接口保存。图的顶部专门标注此原则，省略返回箭头不代表模型能自动保存或覆盖正文。
