# 创作者用例图与规约一致性说明 V0.1

供内部审核，非论文正文。建议图题：**图3-2 创作者用例图**，由Word另行添加，图内仅保留系统边界名称。

## 1. 依据与表示方式

以人工审核通过的3.2.1创作者功能需求分析V0.1为直接依据，结合PROJECT_CONTEXT v1.7、当前研究规划、正式任务书、提交指导老师版开题报告、学校写作指导、第3章规划、3.2概述、功能结构说明和第2章合并稿核对边界。用户后续确认的灵石永久解锁规则继续有效，不因基线尚未同步而撤销。

矩形表示“小说智能辅助创作系统”的边界，椭圆表示24个用例，小人表示创作者；关联均为无箭头实线。图不表达操作先后，也不绘制数据库、模型、MCP或Web框架参与者。本轮没有需要强制表达的include/extend关系，因此不添加此类关系，不将登录、保存或作者确认一概画为所有用例的包含关系。

为减少两列之间的长线交叉，**左右两个同名“创作者”符号是同一参与者的重复显示，不是两类用户、两个账号或不同权限角色**。左右均可执行所连用例，排版分列不构成功能权限划分。此说明应在最终插图后的说明文字中保留。未新增管理员或读者分析。

| 正文编辑与稿件管理 | 编辑与保存正文；导入与导出稿件；查看与恢复历史版本；检索创作内容 | UC-C03说明编辑保存，UC-C04细化TXT导入。导出、历史与检索继续保留，不因未各自制表而删除 |
| 创作资料管理 | 管理人物及人物关系；管理世界观与大纲；管理素材与灵感 | 对应3.2.1第（4）组，素材和灵感没有被大纲替代 |

图中合并名称是需求级聚合，不规定页面数或后台模块拆分。例如“导入与导出稿件”包含两个可独立发起的操作，并非导入必须先于导出。MCP是AI资料访问约束，不增设“MCP协议管理”业务用例。

## 3. 六表对应与关键约束

| 编号 | 规约名称 | 审核重点 |
| --- | --- | --- |
| UC-C01 | 用户注册与登录 | 注册验证码、邮箱密码登录、错误反馈；已有账号直接登录，不预设JWT实现 |
| UC-C02 | 作品与章节管理 | 创建、维护、排序及归属检查；独立操作分别反馈，删除规则不擅定 |
| UC-C03 | 正文编辑与保存 | 手动/自动保存、状态、失败保护；不承诺关闭浏览器后的离线恢复 |

每表十字段齐全，基本流程写正常情形，取消/失败分支和后置条件分开。规约没有性能数据、实际通过状态或AI效果结论。权益永久解锁已获用户确认，不是本轮擅自增加；价格、奖励、保存周期、TXT容量等仍待设计。管理员具体权限仍未在本轮定义。

## 4. 学校格式与正文衔接

学校写作指导PDF第11页要求主要功能用例图、用例规约表及动宾式用例名称。本图采用UML边界、小人、椭圆和实线关联，各业务用例以操作命名，六项AI名称加“进行”以表达动作，未改变Skill名称与含义。

建议后续在3.2.1适当位置引入“创作者用例关系如图3-2所示”，并配合六表说明主要场景；当前锁定正文未修改。Word中的规约表使用普通完整边框，不使用三线表。表号和引表语后续统一安排；本轮不自行占用未确定表号。

## 5. 图片尺寸及实际预览

- SVG：1500×1300画布；PNG：4500×3900像素，300 DPI。两者来自同一套矩形、线、小人、椭圆和文字元素；SVG不引用网络资源。
- 已实际打开PNG检查，宋体中文正常，24个用例文字未溢出或重叠。关联线从参与者手部连接椭圆边界，不穿过文字和其他椭圆。
- 每侧关联线在同一参与者端点汇聚，这是共同参与者的连接端；除该公共端点外，关联线之间无交叉。关联线穿越矩形系统边界属于参与者在系统外的正常画法，不代表用例间关系。
- 白色背景、深灰线条、统一椭圆，无箭头、渐变、阴影或装饰。左右小人重复显示同一角色的说明见第1节，不将其计为两个参与者。
- Word建议宽约16厘米、锁定比例，高约13.9厘米；34画布字号折合约10.3磅。内容较多，不宜再缩小；实际可用宽度不足或学校要求与正文同号时，需人工评估横向排版等版式安排，不通过无限缩小文字处理。最终纸面清晰度还需在Word导出后检查。
- 优先使用SVG；跨机器如缺少宋体须检查字体替换，PNG已固定字体外观。图号图题不在图片内。
