# 3.2.1 创作者功能需求分析

（1）账号与工作台

创作者需要通过邮箱注册账号，经验证码验证后使用邮箱和密码登录，进入个人创作空间。账号功能应支持登录状态保持、记住登录状态、修改密码、个人资料维护和主动退出。忘记密码时，用户通过邮箱获取验证码，验证身份后设置新密码。工作台应提供最近作品和章节的入口，呈现今日及累计创作字数、当前目标、计划进度和近期创作记录，使作者能够找到正在进行的写作任务。工作台中的作品与进度信息均应对应当前登录用户。

（2）作品与章节管理

创作者需要在同一账号下管理多部作品，录入并维护名称、封面、类型、简介、目标字数和创作状态等基本信息，支持新建、查看、修改和删除作品。进入某部作品后，应能按照卷与章节组织正文，创建卷、修改卷信息、调整卷顺序，并在卷下创建和管理章节。章节管理需要提供标题修改、顺序调整、状态维护和删除等操作，同时显示章节字数及最近编辑时间，便于作者查找写作位置。章节正文编辑与目录管理应使用一致的作品和章节归属，避免切换作品后操作对象混淆。创作者只能管理本人有权访问的作品、卷和章节，不能通过改变访问对象取得其他用户的内容。

（3）正文编辑与稿件管理

正文编辑应提供富文本写作能力，支持作者输入、修改章节内容并切换编辑章节。作者可以主动保存，系统也需要提供不干扰正常输入的自动保存，并反馈最近保存状态和当前字数。保存结果应与实际操作一致，失败时应给出提示，避免作者将未保存内容误认为已经保存。章节历史版本需要支持记录、查看和恢复，使作者在修改后能够回看此前稿件，并按需要恢复内容。

已有稿件导入以TXT为第一版格式，支持整本作为单章节导入，以及按章节标题自动分章。解析后应先展示预览，允许作者检查内容和章节划分、进行必要调整，再确认导入。未确认、取消或解析失败的内容不能直接覆盖已有稿件。导入后的作品与章节应按系统中新建内容的相同方式管理，继续用于编辑、版本记录和智能辅助。稿件导出以TXT为基础，供作者保存自己的作品。基础检索还应覆盖作品、章节标题和正文，以及人物、世界观等设定内容，查找范围限于作者有权访问的资料。

（4）创作资料管理

人物档案需要记录身份、性格、目标和经历等设定，人物关系则说明角色之间的联系及关系内容。世界观资料用于维护背景、地点、势力、能力体系和世界规则等信息；大纲管理同时覆盖整体故事安排及分卷、分章的情节计划。这些资料应归属于相应作品，允许作者查询、修改和持续维护，在编写新章节时查阅此前设定。大纲中的计划与正文中已经发生的情节应有所区分，不能将设想直接视为既有故事事实。

素材管理与灵感记录分别承担写作取材和即时想法保存的用途。作者需要整理、维护和查阅自己的素材，按需要关联作品；尚未整理成正文的情节想法可先记录为灵感，之后继续修改和使用。素材和灵感不能仅用人物档案或大纲代替。相关资料既供作者查阅，也可在授权范围内作为智能任务的创作背景，但不因参与AI辅助而改变原有的数据归属。

（5）写作计划与个人统计

写作计划应围绕作品设置总目标字数、每日目标、截止日期和写作任务，并结合实际创作记录展示已完成、剩余目标及任务状态。个人创作统计与分析仅使用当前登录创作者本人在系统中产生的真实业务记录，支持全部作品或指定作品范围。数据总览应呈现作品总数、章节总数、累计创作字数、本月新增字数、当前连续创作天数和计划完成率；作品情况展示各作品名称、当前总字数及章节数量，计划完成情况则对应字数目标、已完成字数和完成率。

作者还需要查看近7天或近30天的每日新增创作字数，以及本月创作天数、当前和最长连续创作天数、日均及单日最高创作字数。历史新增字数应依据真实创作记录统计，不能由章节当前总字数倒推，也不能因重复保存而重复累计。趋势时间选择仅作用于相应趋势数据，其他指标需标明各自统计期间。AI使用情况应区分六项Writing Skill的使用次数、总调用次数、候选采纳次数及采纳率，以真实调用和作者确认记录为依据。采纳情况反映作者对候选的使用，不能解释为生成质量评分；拼字比赛成绩由独立业务处理，不并入该统计模块。

（6）创作激励与沉浸体验

创作激励以签到、写作目标和拼字活动为主要场景，需要记录每日签到、连续签到情况，并按相应规则处理奖励。灵石作为系统内激励积分，应提供余额、获得与消耗记录，说明来源、用途和发生时间。作者可用灵石兑换编辑器或工作台主题皮肤、背景音乐、头像框和创作称号等权益，原有禅模式主题也继续保留。上述权益采用永久解锁方式，兑换成功时扣除对应灵石并永久绑定账号，之后可重复使用、切换，无需再次扣除灵石。同一永久权益不能重复兑换，余额不足时不能完成兑换，兑换失败不得扣除灵石；收支及兑换记录应保留以便查阅。具体价格和奖励数值另行确定，核心写作与智能辅助功能不以灵石为使用门槛。

禅模式应减少与当前写作无关的界面元素，保留章节标题、正文、字数、保存状态和退出入口。背景音乐应支持播放、暂停、切换、音量调节及当前播放状态展示，作者可以选择基础音乐或已解锁内容；基础禅模式和基础音乐可直接使用。拼字房间支持拼字数与拼时间两种模式：前者比较谁先达到目标新增字数，后者在规定时间结束后比较新增字数。系统需要支持创建、加入、成员准备、开始、进度展示、结束结果与房间内排名，并按规则处理奖励；超时未开赛的房间应失效或解散。拼字仅服务于写作激励，不扩展为聊天或交易场景。

（7）智能辅助创作

智能辅助由创作者主动选择任务并提交要求，通过六项Writing Skill分别组织。大纲规划用于根据作品设想和已有设定，提供整体结构、分卷安排与剧情节点建议；人物塑造用于补充角色性格、目标、经历及关系，使作者有可供选择的人物构思；情节构思结合当前剧情和大纲，提供推进方向或事件建议。上下文续写需要承接当前正文，参考相关设定和前文生成后续候选；文本润色针对作者选中的文本及修改目的，提供对白、描写或表达调整建议；一致性检查则对照人物、世界规则和已有事件，提示正文或候选中可能存在的冲突，并提供可核对的依据，供作者判断是否修改。

不同任务应使用与其目的相关的背景，系统需要将作者要求、当前编辑内容与必要的已保存资料共同用于辅助。当前尚未保存的正文及选中文本可直接作为本次输入，不要求为发起AI任务先保存稿件。已保存的作品设定、人物关系、大纲、章节和已有可用摘要应按权限访问，再由Context Management组织。上下文续写与一致性检查须通过真实MCP协议链路取得相关资源和查询结果，保留既定Streamable HTTP通信要求，具体接入设计在后续章节展开。

模型输出应以候选文本、建议或检查提示展示，作者可采用、修改、重新生成或放弃，只有确认后的内容才进入正式保存流程。若等待结果期间正文已经变化，采用候选时仍需由作者确认其适用位置，不能以旧结果静默覆盖新稿。资料不足或调用失败时应明确反馈，保留当前编辑内容；一致性提示也需作者结合原文复核，不能将未发现冲突解释为全书不存在矛盾。
