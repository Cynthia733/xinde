# 2.2 后端相关技术

本系统后端负责接收前端请求、处理业务逻辑和访问数据库，为用户认证、作品与章节管理、创作资料管理及智能创作辅助提供服务。本系统后端基于Java 17进行开发，以Spring Boot组织应用，结合Spring MVC处理接口请求，使用MyBatis-Plus完成常用数据访问。JWT用于身份认证，Swagger/Knife4j拟用于接口文档与开发调试，各项技术共同服务于前后端之间的业务交互。

## 2.2.1 Spring Boot

Spring Boot是在Spring基础上用于组织和运行应用的开发框架。其自动配置会根据项目依赖及相关配置提供常用组件的默认设置，开发者也可以按应用需要进行调整。Starter将某类功能常用的依赖集中组织，减少项目初始化时逐项选择组件的工作。[Spring Boot自动配置说明](https://docs.spring.io/spring-boot/3.5/reference/using/auto-configuration.html)

当前工程采用Spring Boot 3.5.16，并引入Web及MyBatis-Plus相关依赖。本系统包含认证、作品与卷章节、创作资料、写作计划和个人创作统计等业务，也需要为智能辅助与轻量管理员提供接口。采用Spring Boot作为后端基础框架，可在同一应用中组织这些业务，配合配置文件管理运行参数，并通过Maven统一管理依赖。Web请求处理与数据访问分别由相应组件承担，业务服务负责连接具体操作与数据处理。

已有学生德育量化考核系统采用Spring Boot、MyBatis与Vue完成Web应用的设计与实现，为前后端分离系统的工程组织提供了案例参考[P11]。本系统结合小说创作需求选择上述框架，拟按业务划分服务，并统一安排接口响应和异常处理，使前端能够根据返回信息展示数据及操作状态。

## 2.2.2 Spring MVC

Spring MVC是Spring体系中基于Servlet的Web框架，主要处理HTTP请求与响应。[Spring MVC官方说明](https://docs.spring.io/spring-framework/reference/web/webmvc.html)在Spring Boot组织的后端应用中，它负责将请求分配到相应的控制器，并完成参数接收和结果返回。本系统采用前后端分离方式，页面展示由Vue负责，后端主要通过接口交换业务数据，因此拟使用Spring MVC构建Web接口层。

系统接口围绕作品、章节和创作资料等业务对象进行RESTful设计，结合请求方式表达查询、保存和修改等操作。前端提交请求后，Controller接收参数并调用相应的Service，由业务服务处理具体规则，再将结果以统一的JSON结构返回。例如，章节保存需要处理正文与所属作品的关系，智能辅助请求需要进入相应任务流程，这些业务处理由服务层承担。

统一响应与全局异常处理用于协调接口返回方式，使前端可以区分业务数据、操作提示和异常信息。注册登录、作品查询及正文保存等页面由此使用一致的接口交互方式，同时保留各项业务自身的处理要求。

## 2.2.3 MyBatis-Plus

MyBatis-Plus是在MyBatis基础上提供常用数据访问能力的持久层工具，支持基础增删改查、条件构造和分页等功能。开发者可以通过Mapper组织数据访问，并按需要扩展查询逻辑。[MyBatis-Plus官方介绍](https://baomidou.com/introduce/)对于多种业务对象反复使用的基础操作，这种方式可以减少重复编写相近的数据访问代码。

当前工程采用MyBatis-Plus 3.5.17，引入适用于Spring Boot 3的Starter。本系统需要持久化用户、作品、卷章节及人物、世界观和大纲等资料，也需要保存写作计划和AI辅助相关业务记录。这些对象具有较多查询与维护操作，因此拟使用MyBatis-Plus连接业务服务与MySQL，将数据访问集中到相应Mapper中。

作品列表和章节列表可结合条件查询与分页组织返回数据，业务服务则负责确定当前用户及作品范围，避免将访问范围直接交由前端决定。涉及多类记录汇总的创作统计，可按实际需求编写专门查询。具体数据结构将在数据库设计中确定，分页等能力也需结合工程配置使用。

## 2.2.4 JWT身份认证

JWT是一种用于在通信双方之间传递声明的令牌格式，可用于前后端分离系统中的身份认证。本系统拟采用的签名JWT通常由Header、Payload和Signature三部分组成，分别记录令牌信息、声明内容和签名。后端通过验证签名检查令牌的完整性和来源，Payload本身通常经过编码而非加密。[RFC 7519](https://www.rfc-editor.org/rfc/rfc7519.html)

本系统采用邮箱账号体系，拟在用户通过邮箱和密码认证后由后端签发JWT，前端在后续请求中携带认证凭证。后端校验令牌及有效期，识别当前用户，并结合角色和业务规则检查操作权限。例如，创作者访问作品与章节时需要核对数据归属，管理员接口则根据对应角色限制访问。邮箱验证码用于注册验证和密码找回等流程，与登录后的接口身份校验共同构成认证过程。

登录状态保持、主动退出及令牌生命周期将结合认证流程统一设计，前端根据后端认证结果呈现相应操作状态。

## 2.2.5 Swagger/Knife4j

OpenAPI用于描述HTTP接口，Swagger相关工具围绕接口描述提供文档等支持，Knife4j则提供接口文档展示与调试界面。[OpenAPI说明](https://swagger.io/docs/specification/v3_0/about/)及[Knife4j官方文档](https://doc.xiaominfo.com/docs/quick-start)前后端分离开发需要明确请求地址、请求方式、参数、返回结构和认证要求，接口文档可作为双方核对调用方式的依据。

本系统拟采用Swagger/Knife4j整理后端接口文档，配合作品管理、章节编辑及智能辅助等功能的开发。前端可根据文档组织请求，开发过程中也可通过调试界面查看参数与响应，定位接口调用问题。文档内容应随接口调整同步维护，并与后续功能测试相互配合。当前该工具属于技术方案，尚未加入工程依赖，本节仅说明其用途。
