# 2.4 大语言模型相关技术

本系统拟将大语言模型的文本处理能力与小说创作业务结合，通过Writing Skill组织辅助任务，通过Context Management准备任务所需的创作背景。模型负责生成候选内容或检查结果，作者负责判断和确认；系统中已保存资料的访问则与MCP协议链路衔接。

## 2.4.1 大语言模型

大语言模型（Large Language Model，LLM）是一类通过大量数据训练的语言模型，能够学习文本中的语言规律，并根据输入上下文处理和生成文本。现有模型广泛采用Transformer架构，其中自回归生成模型根据已有内容逐步预测后续文本，可用于问答、内容生成和改写等任务[P01]。对于小说创作，这种能力可以提供表达和构思上的候选，而具体任务仍需要明确的要求与相关故事资料。

已有研究将模型嵌入故事编辑工具，通过预设与自定义操作支持续写、扩展和改写，体现了语言模型参与作者写作过程的一种方式[P13]。本系统拟调用外部LLM，为大纲规划、人物塑造和情节构思提供建议，为上下文续写、文本润色提供候选文本，并辅助分析一致性问题。这六项任务是本项目围绕创作流程确定的分类，模型承担其中的文本生成与分析工作。

小说内容随着章节推进不断积累，人物经历、事件顺序和世界规则之间存在较长距离的联系。长故事研究区分了局部表达流畅与整体内容一致，并分析了人物、时间和世界设定等方面的矛盾[P15]。本系统因此需要围绕当前任务组织输入，而非仅依赖模型记住此前所有内容。对于故事中的合理新增情节，应结合作者意图与既定设定判断，不能直接作为生成错误。

本系统将LLM定位为辅助工具，模型返回的建议、文本和检查提示均供作者参考。作者可以采用、修改、重新生成或放弃，确认后的内容再通过正常业务流程保存。这样的使用方式将生成与正式稿件管理分开，使最终内容的决定权保留在作者手中。

## 2.4.2 Writing Skill

Writing Skill是本系统用于组织小说智能创作任务的应用层设计。不同任务需要处理的文本范围、创作要求和返回内容并不相同，将其分别组织有助于明确一次辅助操作要完成什么。系统拟为各项Skill安排输入要求、资料需求、任务指令、输出形式与结果处理，使作者能够通过相应入口提交要求，而不必每次重新说明全部任务背景。

提示学习研究讨论了通过任务描述、示例及模板表达任务要求的方式[P05]；Wordcraft也将预设操作和作者自定义要求结合到故事编辑过程中[P13]。这些研究为任务表达和交互组织提供了参考。本系统的Writing Skill则面向后端业务编排，负责连接作者输入、上下文准备、模型调用与候选处理，并以外部模型调用为基础开展辅助。

六项Skill按用途分为三组。大纲规划、人物塑造和情节构思主要服务于创作准备与构思，提供结构、人物或剧情方向的建议；上下文续写和文本润色围绕已有正文，分别生成后续候选或调整选中文本的表达；一致性检查结合已有设定与章节内容，提示可能存在的矛盾。这些任务都由作者按需发起，其输出是可供选择的建议或辅助判断。

例如，续写任务需要明确当前写作位置与推进要求，润色任务则需确定选中文本和修改目的。Skill将这些要求交给上下文管理与模型调用环节，并按任务用途呈现结果。作者确认后，候选才进入相应的正文或创作资料保存流程；未被采用的结果不覆盖正式内容。具体任务流程及提示组织将在系统设计章节中展开。

## 2.4.3 Context Management

长篇小说的创作背景分布在作品信息、人物及关系、世界观、大纲和章节正文等资料中，已有章节摘要也可为回顾前文提供参考。不同任务关注的内容不同，直接提交全部资料既难以突出当前要求，也受到输入规模和处理开销的限制。长文本推断研究讨论了长输入涉及的计算与存储开销[P08]；Re³则在长故事生成中动态组合计划与此前故事状态，为下一段生成准备背景[P14]。

本系统借鉴按生成阶段组织相关信息的思路，将Context Management设计为任务上下文管理部分。它根据当前Skill和写作位置确定资料需求，取得相关内容，进行必要的选择、裁剪与组合，并控制输入规模。组织时区分已确认设定、已有正文、大纲计划和章节摘要，避免将计划中的情节直接当作已经发生的事实。摘要按其来源章节及更新情况使用，当前编辑器内容和作者要求则作为本次任务的直接输入。

在上下文续写中，系统拟结合当前正文、邻近的前文章节、人物设定及必要的情节资料，为模型提供承接背景。在一致性检查中，则围绕人物关系、世界规则和已有事件组织参照内容，与待检查文本共同输入。模型给出的冲突提示仍可能存在遗漏或误判，需要作者结合原文复核。上下文管理的作用是准备适合当前任务的信息，其实际效果由后续系统测试检验。

Context Management与MCP分别承担内容组织和资料访问职责。前者决定需要哪些上下文以及如何组合，后者通过规范化协议接口访问系统内已保存的创作资源和必要查询工具。按本项目方案，上下文续写与一致性检查需实际经过MCP协议链路取得相关资料，再与当前请求中的编辑内容、选中文本和作者要求合并。当前输入可直接进入上下文管理，无需先保存再读取。下一节将介绍MCP协议及其在这种访问方式中的作用。

## 3. 职责与范围检查

- **LLM：**提供文本生成和分析；没有预设可靠长期记忆、全部冲突识别能力或生成质量提升。
- **Writing Skill：**六项完整保留为大纲规划、人物塑造、情节构思、上下文续写、文本润色、一致性检查。属于C类后端任务组织，不是行业标准、模型固定能力、插件或MCP组成部分。
- **Context Management：**按任务准备资料并选择、组织和控制输入规模；当前正文、选中文本与作者要求可直接进入。章节摘要的生成方式没有锁定，不新增自动摘要算法。
- **MCP：**按项目既定方案通过真实协议访问已保存创作资料和必要工具，与内容选择分工。未写成普通Java调用、改名REST、提示模板或向量数据库；没有用上述论文证明协议有效。
- **作者确认：**候选由作者决定采用、修改、重新生成或放弃，经普通业务流程保存；没有模型自动写入或覆盖正式正文的表述。
