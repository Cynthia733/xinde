# 3.1 可行性分析

## 3.1.1 技术可行性

本系统的创作界面可由Vue 3及相关前端技术组织，将作品管理、章节编辑、资料维护和候选展示安排在同一应用中。Java 17与Spring Boot作为后端基础，配合Spring MVC处理业务接口，MyBatis-Plus衔接数据访问，MySQL按业务关联保存用户、作品、章节及创作资料。当前工程已有后端基础依赖配置，可据此逐步开发业务模块。智能辅助拟调用外部LLM，无需自行训练模型；Writing Skill组织六项创作任务，Context Management准备相关上下文。MCP Client与Server拟在同一Spring Boot应用中通过真实Streamable HTTP回环通信获取已保存资料。现有方案具备实施基础，但MCP SDK与Spring MVC的适配、模型接口接入和完整业务流程仍需在开发与测试中确认。

## 3.1.2 经济可行性

本课题可利用现有计算机与开发环境开展基础开发，已选定的Java、Vue、Spring Boot和MySQL等技术也为后续工作提供了工具选择范围，具体使用应遵循相应许可条件。系统采用单体Web应用，部署与维护主要围绕前端、后端和数据库展开，无需为本课题另行训练模型或建设训练环境。运行支出仍需考虑外部模型调用、验证码邮件发送，以及后续服务器资源费用。开发中可结合需要控制模型调用频率、输入规模和部署资源，减少无必要的消耗。在确定服务商与实际用量后核算费用，并据可承担预算安排验证，才能进一步确认经济可行性。

## 3.1.3 操作可行性

系统以PC浏览器为主要入口，拟围绕工作台、作品和章节组织导航，使作者能够从当前作品进入正文编辑，并查阅或维护人物、世界观和大纲等资料。智能辅助由作者按需要主动发起，生成内容先作为候选展示，再由作者选择采用、修改或放弃，避免将生成与正式保存混为一次操作。个人创作统计用于查看自身记录，保存状态及必要提示用于反馈当前操作结果。上述安排将创作对象、辅助任务和内容确认联系起来，具备形成清晰操作流程的条件。后续仍需通过实际页面与操作验证检查导航、保存提示及候选处理是否符合设计要求。

## 3.1.4 社会可行性

本系统服务于小说构思、资料整理和正文修改，将大语言模型定位为辅助工具，正式内容仍由作者决定。使用中应关注生成结果是否存在事实错误、设定冲突或偏离创作意图的情况，并将合理的情节创新与错误区分，由作者检查和选择。对私人稿件及创作资料，系统需要限制访问范围；调用外部模型时，还应核对服务的数据使用条件，只提交任务所需内容，不能将接口可用等同于隐私风险已经消除。导入的TXT稿件以及背景音乐等资源也应具有合法来源和相应使用权限。在保留作者决定权、落实资料保护并合理使用资源的前提下，该系统作为小说辅助创作工具具有实际使用的合理性。
