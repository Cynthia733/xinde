# 前言

文本构思与改写是数字内容创作过程中的常见环节。大语言模型具备语言理解与文本生成能力，为这些环节提供了辅助工具的技术基础[P01]。网络文学作者的访谈研究也记录了素材准备、大纲构思和续写等使用情境[P09]。小说写作往往跨越多个章节，人物经历、世界规则与情节线索随创作持续积累。作者不仅需要写出当前段落，还需回顾既有内容，判断新的叙述是否符合此前设定。这些操作贯穿持续创作过程。

已有研究从人机协同故事写作和自动长故事生成等角度探索模型应用：任务控件可将生成与修改嵌入编辑过程，规划和动态上下文则用于组织连续生成所需的信息[P13][P14]。这些探索并未消除长篇叙事的困难，局部表达流畅仍可能伴随人物、时间或世界规则冲突[P15]。此外，部分受访作者会主动限定AI的使用范围，并以自身构思指导生成，提示辅助工具还需关注作者的选择与控制[P09]。

从软件工程角度看，单次文本生成难以覆盖小说持续创作过程中的完整业务需求。针对本课题，资料如何随作品维护、不同任务如何取得所需上下文、候选内容如何进入正式稿件，均需在系统中明确处理。本文围绕小说创作工作流开展系统设计与实现研究，将创作管理与大语言模型辅助相结合，以Writing Skill组织任务，通过上下文管理机制和MCP访问所需资料与工具。研究关注模型能力与日常写作操作的衔接，以作者确认作为候选入稿的必要环节，使修改、采用和保存的决定留在作者手中。
