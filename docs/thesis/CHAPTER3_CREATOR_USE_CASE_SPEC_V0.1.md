# 创作者主要用例规约 V0.1

用例规约用于说明参与者、操作目标、前置条件、主要流程、异常情况及完成后的结果。以下从已锁定的3.2.1中选取六个主要用例，描述系统应提供的行为，不表示功能已经实现。注册与登录保留在同一规约中，以新用户注册后登录为基本流程，已有账号直接登录作为备选流程。

## UC-C01 用户注册与登录

| 字段 | 内容 |
| --- | --- |
| 用例编号 | UC-C01 |
| 用例名称 | 用户注册与登录 |
| 参与者 | 创作者（包含准备注册的用户） |
| 目标 | 建立邮箱账号或使用已有账号登录，进入个人创作空间。 |
| 前置条件 | 用户可访问注册或登录入口；注册时能够接收本人邮箱验证码，登录时已有账号。 |
| 触发条件 | 用户选择注册或登录。 |
| 基本流程 | 1. 用户填写邮箱和注册所需信息，申请验证码。<br>2. 用户输入验证码并提交注册。<br>3. 系统校验邮箱注册信息和验证码，通过后建立账号并反馈结果。<br>4. 用户提交邮箱和密码进行登录。<br>5. 系统核验登录信息，通过后进入该用户的创作空间，展示本人工作台信息。 |
| 备选或异常流程 | A1. 已有账号的用户直接从第4步登录。<br>A2. 验证码无效或注册信息不符合要求时，提示检查并重新提交，不将注册记为成功；邮箱已经注册时提示使用已有账号。<br>A3. 验证码无法取得时，不绕过验证创建账号。<br>A4. 登录信息错误或认证失败时反馈失败，不进入个人创作空间。<br>A5. 忘记密码时，通过邮箱验证码验证身份并设置新密码，再登录。 |
| 后置条件 | 成功：注册成功则建立账号；登录成功则获得本人创作空间的访问状态，两者分别反馈。失败：对应注册或登录操作不生效；注册成功但随后登录失败，不把已经建立的账号解释为不存在。 |
| 关键业务规则 | 使用邮箱账号与密码登录；验证码用于注册验证、密码找回。登录状态保持、记住状态及主动退出沿用账号需求，不保存明文密码，不确定具体令牌存储或续期方案。个人空间不展示其他用户的私人资料。 |

## UC-C02 作品与章节管理

| 字段 | 内容 |
| --- | --- |
| 用例编号 | UC-C02 |
| 用例名称 | 作品与章节管理 |
| 参与者 | 创作者 |
| 目标 | 建立作品并按卷、章节组织内容，维护作品信息及章节目录。 |
| 前置条件 | 用户已经登录；维护已有对象时对该作品、卷或章节具有相应权限。 |
| 触发条件 | 创作者选择新建作品，或进入已有作品进行管理。 |
| 基本流程 | 1. 创作者填写作品名称、简介等信息并提交创建。<br>2. 系统检查输入与用户身份，建立归属于该用户的作品。<br>3. 创作者进入作品，创建卷并在卷下创建章节。<br>4. 系统核对作品、卷和章节的归属关系，保存各次有效操作并反馈。<br>5. 创作者按写作需要修改作品信息、卷信息、章节标题或状态，并调整卷与章节顺序。<br>6. 系统在权限及业务检查通过后更新对应信息，显示最新目录。 |
| 备选或异常流程 | A1. 管理已有作品时直接进入相应作品，不必重新创建；修改和排序按需要分别发起，不要求一次完成全部操作。<br>A2. 缺少必要信息、对象不存在或归属不匹配时，拒绝本次操作并提示。<br>A3. 无权访问时不返回该对象的私人内容，也不执行修改。<br>A4. 保存某次修改失败时反馈失败，不将该次操作显示为成功。<br>A5. 删除作品、卷或章节时，仅在相应权限及业务检查通过后处理；具体关联内容处理规则留详细设计。 |
| 后置条件 | 成功：对应对象创建或更新，归属关系与目录信息一致。失败：本次失败操作不产生成功变更，之前已成功完成的其他独立操作不因此被视为失败。 |
| 关键业务规则 | 作品、卷、章节具有明确归属，创作者只能管理本人有权访问的内容；不编造章节状态枚举、删除级联方式或数据表结构。正文输入与保存由UC-C03说明。 |

## UC-C03 正文编辑与保存

| 字段 | 内容 |
| --- | --- |
| 用例编号 | UC-C03 |
| 用例名称 | 正文编辑与保存 |
| 参与者 | 创作者 |
| 目标 | 编辑有权限的章节正文，并明确了解内容是否保存成功。 |
| 前置条件 | 用户已登录，目标章节存在且具有编辑权限。 |
| 触发条件 | 创作者打开章节进行写作，并主动保存或在编辑过程中触发自动保存。 |
| 基本流程 | 1. 创作者打开章节，系统核对访问范围并呈现正文。<br>2. 创作者在富文本编辑区域输入或修改内容，查看当前字数与保存状态。<br>3. 创作者执行手动保存。<br>4. 系统校验当前用户与章节归属，保存此次提交的内容。<br>5. 系统返回保存结果，页面据此更新保存状态。 |
| 备选或异常流程 | A1. 自动保存按后续确定的策略触发，沿用相同权限与结果反馈要求，不干扰正常输入。<br>A2. 章节无权访问或不存在时，不打开或写入相应私人内容。<br>A3. 保存失败时保留当前编辑内容并显示失败，允许作者之后重新保存，不显示成功状态。<br>A4. 切换章节时仍需区分当前未保存内容与已保存稿件，不能以页面切换或失败反馈静默丢弃未保存输入；具体交互方式留设计。 |
| 后置条件 | 成功：此次提交的正文已保存，页面反馈对应结果。失败：不能认定新内容已经保存；当前编辑内容应保留，已有正式稿件不因失败被覆盖。 |
| 关键业务规则 | 手动与自动保存均保留；不预设自动保存间隔。历史版本记录、查看和恢复沿用已锁定需求，记录时机及保留数量另行设计。此处输入保护不等同于已经具备断电、浏览器关闭后的自动恢复能力。 |

## UC-C04 TXT稿件导入

| 字段 | 内容 |
| --- | --- |
| 用例编号 | UC-C04 |
| 用例名称 | TXT稿件导入 |
| 参与者 | 创作者 |
| 目标 | 将本人已有TXT稿件经预览确认后纳入系统，继续编辑和管理。 |
| 前置条件 | 用户已登录，持有可导入的TXT稿件，并有权创建或操作相应作品内容。 |
| 触发条件 | 创作者选择稿件导入。 |
| 基本流程 | 1. 创作者选择TXT文件，选择整本单章节或自动分章模式。<br>2. 系统读取并解析文本，形成相应的章节预览。<br>3. 创作者检查正文和章节划分，进行必要调整，并明确作品及卷章节归属。<br>4. 创作者确认导入。<br>5. 系统再次核对权限及待导入内容，将确认内容纳入统一作品与卷章节管理，返回导入结果。 |
| 备选或异常流程 | A1. 文件不符合TXT导入要求或无法解析时，说明失败，不写为正式稿件。<br>A2. 预览不合适时，创作者可调整或取消；取消及未确认均不形成正式导入。<br>A3. 权限检查失败时拒绝导入，不修改无权访问的内容。<br>A4. 确认后的导入处理发生异常时反馈失败，不将失败记为导入成功，也不得覆盖已有稿件；部分失败及重复提交的具体处理方案在详细设计中明确。 |
| 后置条件 | 成功：确认的TXT内容成为可正常编辑、管理及用于AI辅助的作品和章节。取消或失败：不覆盖已有稿件，未确认的预览内容不成为正式稿件；异常状态应明确可见。 |
| 关键业务规则 | 两种导入模式、预览与作者确认均保留；导入与新建稿件采用统一业务管理，不另建TXT数据体系。不预设文件容量、编码识别算法、章节正则或默认卷归属。导出仍按既有TXT基础功能保留，本表仅详述导入。 |

## UC-C05 AI辅助创作

| 字段 | 内容 |
| --- | --- |
| 用例编号 | UC-C05 |
| 用例名称 | AI辅助创作 |
| 参与者 | 创作者 |
| 目标 | 围绕当前作品取得可供作者判断的构思建议、候选文本或一致性提示。 |
| 前置条件 | 用户已登录，对所选作品及任务涉及的资料具有权限；任务所需输入可提交，资料缺失须明确处理。 |
| 触发条件 | 创作者主动选择一项Writing Skill并发起辅助请求。 |
| 基本流程 | 1. 创作者从大纲规划、人物塑造、情节构思、上下文续写、文本润色、一致性检查中选择任务。<br>2. 提交任务要求，并按任务需要提供当前正文或选中文本。<br>3. 系统核对权限，按任务使用已有设定、大纲、章节及可用摘要等背景，与当前输入共同组织上下文。<br>4. 系统调用模型，返回并展示候选文本、建议或检查提示。<br>5. 创作者查看结果，决定是否采用，必要时先修改。<br>6. 对需要写入的候选，作者确认内容与适用位置后进入普通保存流程；检查提示由作者复核并决定是否修改原文。 |
| 备选或异常流程 | A1. 创作者选择重新生成时再次发起任务；放弃时不写入正式稿件。<br>A2. 资料缺失或不足时提示实际范围；一致性对照不足不能给出全书无冲突结论。<br>A3. 无权访问资料时终止相应访问，不以其他路径绕过权限。<br>A4. 模型调用失败时说明失败，保留当前编辑内容，不伪造候选或自动保存。<br>A5. 等待期间正文发生变化或候选不适合当前位置时，由作者再次判断并确认位置，或修改、重新生成、放弃，不静默覆盖新稿。<br>A6. 确认后保存失败时按正文或资料保存规则反馈，不将候选确认等同保存成功。 |
| 后置条件 | 成功取得结果：候选或提示已展示，但尚不代表正式稿件已改变。确认并保存成功：仅作者确认的内容进入相应正式内容。放弃、调用失败或保存失败：不得自动以模型结果覆盖稿件。 |
| 关键业务规则 | 六项Skill均保留，具体目的以3.2.1为准。当前未保存正文、选中文本和作者要求可直接作为输入，无需先保存。已保存资料按权限取得，由Context Management组织。上下文续写及一致性检查正常路径须经真实MCP Streamable HTTP协议链路读取资源并调用必要查询工具；不得以普通方法调用冒充，故障处理沿用基线且不能绕过权限。所有输出为辅助结果，不保证消除一致性错误。 |

## UC-C06 灵石权益兑换

| 字段 | 内容 |
| --- | --- |
| 用例编号 | UC-C06 |
| 用例名称 | 灵石权益兑换 |
| 参与者 | 创作者 |
| 目标 | 使用已有灵石永久解锁所选个性化或沉浸权益。 |
| 前置条件 | 用户已登录；存在可供选择的正式权益及其兑换价格信息。价格数值不由本规约确定，余额是否充足在流程中检查。 |
| 触发条件 | 创作者查看兑换入口并选择权益。 |
| 基本流程 | 1. 创作者查看本人灵石余额和可兑换权益。<br>2. 选择主题皮肤、背景音乐、头像框或创作称号等权益，查看所需灵石及解锁状态。<br>3. 系统检查该权益尚未解锁且余额充足。<br>4. 创作者确认兑换，系统在执行时核对余额与解锁状态。<br>5. 兑换成功时扣除对应灵石，将权益永久绑定账号，记录兑换及灵石收支。<br>6. 系统反馈结果；创作者可使用、切换已解锁权益，重复使用不再次扣费。 |
| 备选或异常流程 | A1. 余额不足时不完成兑换，不扣灵石。<br>A2. 权益已解锁时不重复兑换，允许使用已有权益，不再次扣费。<br>A3. 作者未确认或取消时不执行兑换。<br>A4. 兑换过程中异常导致失败时，不得扣除灵石，也不显示解锁成功；不能遗留扣费成功但权益未解锁的失败结果。<br>A5. 重复提交或状态已变化时仍遵守同一永久权益不重复兑换的规则。 |
| 后置条件 | 成功：对应灵石已扣除、权益永久解锁，收支与兑换记录一致。失败或取消：本次不扣费、不产生新的成功解锁，不影响原有已解锁权益。 |
| 关键业务规则 | 权益永久绑定账号，已解锁权益可重复使用与切换，同一权益不得重复兑换。保留收支与兑换记录；具体价格、奖励数量及实现方式另行确定。不引入充值、提现、转账或AI次数购买。失败不扣费是业务结果要求，不在此规定数据库事务或锁实现。 |
