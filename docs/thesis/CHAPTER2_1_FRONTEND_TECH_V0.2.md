# 2.1 前端相关技术

本系统面向小说创作者，采用PC网页优先的前后端分离方式。前端除展示作品和创作资料外，还需要处理正文编辑、页面切换、共享状态、接口请求及个人创作数据展示。系统拟以HTML5、CSS3和JavaScript为基础，由Vue 3组织界面，配合组件库、路由、状态管理、通信和图表工具完成不同职责，使创作操作与后端业务处理相互衔接。

## 2.1.1 HTML5、CSS3与JavaScript

本系统前端以HTML5、CSS3和JavaScript为基础，分别组织页面内容、设置布局样式和处理用户交互。其中，HTML5用于组织导航、表单、正文区域和资料面板，使章节目录、编辑内容与操作入口在页面中具有明确位置。页面结构需要服务于长文本写作，不能只按管理表格的形式排列所有内容。

CSS3主要用于布局、字体、间距和不同操作状态的视觉呈现。例如，正文编辑页面需要协调章节目录、编辑区与辅助面板的宽度，人物和世界观页面则需要清楚区分资料列表与编辑表单。JavaScript用于处理输入、点击、选中及页面数据变化，也是Vue开发的语言基础。三者共同组成前端基础层：结构说明内容放在哪里，样式组织显示方式，脚本响应用户操作。具体页面布局和编辑器组件将在后续设计与实现中确定。

## 2.1.2 Vue 3

本系统拟使用Vue 3构建单页应用。创作者会在工作台、作品资料和章节编辑之间反复切换，同一页面也会出现加载、编辑、保存和等待辅助结果等不同状态。Vue提供声明式、组件化的界面组织方式，并根据响应式数据变化更新相关界面，可用于处理这些交互关系。[Vue官方指南](https://vuejs.org/guide/introduction.html)

组件划分可以围绕业务职责展开。例如，章节目录负责选择编辑对象，正文区域负责显示和编辑内容，AI辅助面板负责提交要求和展示候选。采用组件组织后，各部分可以通过明确的数据和事件关系协作，共用表单或提示界面也能集中维护。响应式更新用于将当前选择、请求状态和返回结果反映到页面，但页面显示发生变化并不等于数据已经保存，保存状态仍需依据后端响应确定。

已有Web系统设计案例采用Vue组织单页前端，通过界面组件与后端接口配合完成业务交互[P11]。这一案例提供了前端应用组织的参考；本系统则结合小说创作需求，拟采用Vue 3组织页面和组件。Vue Router负责页面导航，Pinia管理必要的共享状态，两者与Vue共同形成应用结构；具体编码风格和组件接口在实现阶段细化。

## 2.1.3 Element Plus

本系统包含认证、资料录入和管理等多类页面，其中表单、按钮、对话框、菜单、表格、分页及消息提示具有重复使用的需要。Element Plus提供这些常用组件，可用于统一Vue 3前端中的基础交互。[Element Plus组件目录](https://element-plus.org/en-US/component/overview.html)

在本系统中，邮箱注册和登录页面可使用表单组织输入与提示；作品、人物和世界观管理可结合列表与对话框完成资料查看和编辑；轻量管理员页面可使用表格及分页展示管理对象。选用组件库的原因是这些页面有相近的操作形式，可以复用一致的控件和提示方式，而不是分别编写每个基础控件。小说正文编辑仍需结合长文本和富文本需求设计，不能把通用输入框直接视为完整编辑器。表单提示也只承担前端反馈，业务数据是否有效仍由后端校验。

## 2.1.4 Vue Router与Pinia

Vue Router和Pinia分别处理页面导航与跨组件状态，两者用途不同。Vue Router通过路由配置建立地址与页面组件的对应关系，适用于单页应用中的页面切换；导航守卫可对跳转进行判断。[Vue Router指南](https://router.vuejs.org/guide/)及[导航守卫说明](https://router.vuejs.org/guide/advanced/navigation-guards.html)

本系统拟用路由组织登录、工作台、作品编辑、创作资料、统计及管理员页面，并结合登录状态和角色安排访问入口。路由限制主要控制前端导航，不能替代后端JWT认证和接口权限校验。即使页面入口被隐藏，后端仍须验证请求者是否有权访问对应作品或管理操作。

Pinia用于管理多个组件需要共同使用的状态。[Pinia官方说明](https://pinia.vuejs.org/introduction.html)本系统可将当前用户基础状态、当前作品和章节标识、必要的全局界面状态纳入共享管理，使导航与编辑区域能够使用一致的选择信息。只在单个表单中使用的临时输入不必全部放入全局状态。前端状态也不等于持久化数据，作品内容仍通过业务接口读取和保存。具体Store划分、状态更新与清理方式将在实现时确定，不在本节预设完整结构。

## 2.1.5 Axios

本系统前端需要向Spring Boot后端提交认证、作品与章节增删改查、资料保存、AI辅助及统计查询请求。Axios用于组织HTTP通信，可通过统一请求配置和请求、响应拦截处理公共逻辑。[Axios官方仓库文档](https://github.com/axios/axios#interceptors)

系统拟集中管理接口基础地址和通用响应处理，使页面组件主要关注操作内容与返回结果。需要身份认证的请求按约定携带认证凭证，由后端检查JWT合法性、用户权限和数据归属。Token的存储位置及续期细节尚未锁定，不由请求工具自动决定。对于保存或智能辅助操作，界面需要区分请求等待、成功和失败，不能仅因请求已经发出就提示完成。AI辅助请求同样先进入本系统后端，前端不持有模型服务密钥。Axios承担通信组织职责，业务处理与最终数据校验仍在后端完成。

## 2.1.6 ECharts

创作统计与分析模块需要呈现当前创作者的字数变化、作品进度和AI辅助使用情况。ECharts提供折线图和柱状图等图表形式，可用于将统计结果映射为坐标轴、数据系列和数值提示。[ECharts折线图说明](https://echarts.apache.org/handbook/en/how-to/chart-types/line/basic-line/)与[柱状图说明](https://echarts.apache.org/handbook/en/how-to/chart-types/bar/basic-bar/)

本系统拟使用折线图展示近7天或近30天每日实际新增创作字数，使用柱状图展示各作品当前字数、章节数量及六类Writing Skill使用次数。作品统计支持全部作品或指定作品筛选，近7天和近30天选择用于个人字数趋势。数据总览可使用卡片，计划完成情况可使用进度条，活跃情况与候选采纳数据按信息特点展示，不要求所有指标都绘制成图表。

图表数据全部来自本系统真实业务记录。每日新增字数需依据创作变化记录计算，不能用章节当前总字数替代；AI使用与采纳数据分别依据调用和作者确认记录。ECharts负责展示，不负责定义新增字数或采纳率的统计口径，也不能由采纳率推断生成质量。相关计算规则需在数据设计阶段明确，界面应保持筛选范围、时间说明和数值含义一致。
