## 1. 正式任务书摘要

原件为成都理工大学工程技术学院2027届毕业论文（设计）任务书。主要任务原文分为六项：

1. “完成系统需求分析与总体设计，基于Spring Boot+Vue实现前后端分离架构，完成用户注册登录、角色权限、作品与章节管理等基础模块”。
2. “研究面向小说创作的大语言模型Skill（技能）设计方法，梳理大纲构思、情节续写、人物设定、文风润色等技能的提示词与调用流程”。
3. “研究MCP（模型上下文协议）的工具接入方式，将小说设定资料、素材库等资源封装为可调用工具，实现智能体按需存取”。
4. “基于Skill与MCP实现AI辅助创作功能，生成结果支持人工编辑与重新生成”。
5. “实现普通小说写作功能，包括富文本编辑器、素材管理、灵感速记与章节版本管理”。
6. “系统主要页面响应时间≤2秒，支持多用户并发使用，完成功能测试与使用验证”。

作品要求为可运行Web系统，交付完整源代码、Skill/MCP工具设计说明、数据库文档/建表脚本/部署说明、功能测试记录与操作演示，配合完整毕业论文。

任务书是最低范围，不是功能上限。原文“等技能”及“等基础模块”不构成删减六类Skill或v1.5正式功能的依据。任务书“选题意义或目的”中的行业性判断只作为任务背景，不直接补入论文当作已核验学术事实。

## 6. MCP V1.0最终方案

MCP作为智能辅助模块访问创作资源和必要工具的标准化协议边界，不替代Service、REST、数据库框架。Client在后端AI模块，Server嵌入同一Spring Boot应用；沿用Streamable HTTP真实MCP消息通信与内部端点，不新增微服务。SDK/API及内部类名在Java 17、Spring Boot 3、Spring MVC兼容核验后选择，职责不变。

普通业务链：Vue → REST API → Controller → Service → MyBatis-Plus → MySQL。

AI链：Writing Skill → Context Management → MCP Client → MCP Server → 创作资源/查询Service → Context Management → Prompt Builder → LLM → 候选结果 → 作者确认 → 普通业务接口保存。

正式Resource候选及语义：

| URI模板 | 资料 |
|---|---|
| `novel://works/{workId}/overview` | 作品概况 |
| `novel://works/{workId}/characters` | 人物设定 |
| `novel://works/{workId}/relationships` | 人物关系 |
| `novel://works/{workId}/world` | 世界观 |
| `novel://works/{workId}/outline` | 大纲 |
| `novel://works/{workId}/chapters/{chapterId}` | 已保存章节 |
| `novel://works/{workId}/summaries/{chapterId}` | 已有章节摘要及来源/有效性 |

URI可按SDK规范微调，语义保持。素材、灵感等所需资料纳入资源访问体系，具体契约在详细设计补齐，不为增加数量机械复制Tool。

必须实现 `get_chapter_window(workId, anchorChapterId, previousCount, includeExistingSummaries, maxChars)`：取得锚点前的有界章节及已有摘要，限制数量与长度，附来源和截断/缺失信息；不生成摘要、不保存正文。现有当前编辑文本由Context Management合并。只有真实业务需要才增加少量工具。

上下文续写和一致性检查在关闭fallback时，均必须经真实Resource读取与Tool调用获取资料并送入模型输入。保留初始化/能力发现/资源读取/工具调用和业务请求关联证据；不可用同名Java方法直调或伪造日志替代协议。

保留v1.5权限、追踪、超时和降级设计：Server校验可信用户/作品范围，不因回环地址放弃鉴权；临时故障可显式等价本地读取，授权失败不得降级绕过；降级不能计入正常MCP通过证据，也不能解决整个应用或数据库宕机。

## 7. “智能体按需存取”的项目解释

对应任务书任务（3）。本项目以确定性的智能创作任务按需获取设定、人物关系、世界观、大纲、章节、摘要及素材等资料和查询工具，落实该表述。不增加Multi-Agent、自动协商或自主规划Agent框架；论文中的“智能体”必须与这一实际流程相符。

任务书广义“资源封装为可调用工具”落实为Resource资料读取与Tool参数化查询两类能力，不是删去素材访问。“存取”不赋予模型自动覆盖正式稿件的权利：生成候选经作者采用/修改后，由普通业务接口保存。当前MCP重点为读取与必要查询，不默认提供写稿Tool。

## 8. Context Management定位

按Skill需要选择、裁剪、组合信息并控制预算，包含当前作者要求、编辑器内容、选中文本、作品设定、人物关系、世界观、大纲、当前和前文章节、已有章节摘要及必要素材。

直接请求输入无需先存库或绕经MCP。系统已有创作资料主要经MCP取回，再由Context Builder组织，不能把MCP当自动上下文策略。摘要只在存在且有效时使用，不因本次同步强制模型自动生成摘要。候选仍由作者采用、修改、重新生成或放弃；未经确认不能覆盖正文。

## 9. TXT导入正式需求

定位为创作者导入本人已有稿件；不是管理员批量建立公共小说库。支持整本单章节及标题规则自动分章两种模式。常见标题包含“第一章”“第十二章”“第123章”“Chapter 1”，具体正则与兼容规则尚待实现确定。

流程：选择TXT → 上传 → 读取/编码处理 → 章节解析 → 解析预览 → 作者检查/调整 → 确认 → 创建作品/卷章节 → 正常创作。确认前不直接将全部内容写成正式章节；卷组织默认方式、临时预览存放、文件限制和失败处理后续详细设计。

同一作品/章节数据模型必须支持后续编辑、卷章节管理、版本历史、六类Skill、Context Management、MCP章节访问及续写/一致性检查。不建立独立TXT数据库。导入仅TXT；稿件导出保留原TXT基础与Markdown可扩展、Word非必做的确定程度。
